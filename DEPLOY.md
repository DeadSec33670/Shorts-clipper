# Развёртывание в открытый доступ

Документ описывает **Этап 1** — безопасный запуск наружу. Ограничения этого
этапа (одна обработка на всех, общие клипы) снимаются на Этапе 2, см. `AUDIT.md`.

---

## Два режима работы

Приложение различает их по переменной `CLIPPER_PUBLIC`.

| | Локальный (по умолчанию) | Публичный (`CLIPPER_PUBLIC=1`) |
|---|---|---|
| Пути к файлам на диске сервера | доступны | **запрещены** |
| Куки браузера для yt-dlp | доступны | **запрещены** |
| Cookie сессии `Secure` | выключено | включено (нужен HTTPS) |
| Ключ подписи сессий | файл `.flask_secret` | только `CLIPPER_SECRET_KEY` |
| Заголовок HSTS | нет | есть |
| Запуск `python web.py` | работает | **блокируется**, нужен gunicorn |

Ваш текущий рабочий процесс на Windows **не меняется**: без переменной всё
работает как раньше.

---

## Что уже сделано (Этап 1)

1. **Закрыто чтение произвольных файлов.** Поле «пути к файлам» и параметры
   куков в публичном режиме отключены и вырезаются из разметки.
2. **Исправлен обход проверки пути** при удалении клипов (`is_relative_to`
   вместо `startswith`, который пропускал соседние папки).
3. **CSRF-защита** — токен в сессии плюс проверка `Origin`/`Referer` на всех
   изменяющих запросах.
4. **Ограничение перебора паролей** — 7 попыток за 15 минут по IP и по email.
5. **Безопасные cookie** — `HttpOnly`, `SameSite=Lax`, `Secure`, срок 7 дней,
   смена идентификатора сессии после входа.
6. **Лимит и проверка загрузок** — 2 ГБ, белый список расширений, имена файлов
   генерируются сервером (исключены коллизии между пользователями).
7. **Проверка аргументов** — белые списки для провайдера, модели, длины,
   запрет значений, начинающихся с дефиса (иначе через поле «шрифт» можно было
   дописать в команду произвольный флаг).
8. **Заголовки безопасности** — CSP, `X-Frame-Options`, `nosniff`, HSTS.
9. **Боевой сервер** — конфиги gunicorn, nginx, systemd.

Проверить всё разом: `python tests_security.py` — должно быть 23 из 23.

## Установка на сервер (Ubuntu 22.04+)

### 1. Система

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip ffmpeg nginx certbot python3-certbot-nginx
sudo useradd -r -m -d /opt/shorts-clipper -s /usr/sbin/nologin clipper
```

### 2. Приложение

```bash
sudo -u clipper git clone <ваш-репозиторий> /opt/shorts-clipper
cd /opt/shorts-clipper
sudo -u clipper python3 -m venv venv
sudo -u clipper venv/bin/pip install -r requirements.txt gunicorn
```

Для GPU ставьте PyTorch отдельно под свою версию CUDA (см. `README.md`).

### 3. Секреты

```bash
sudo cp deploy/env.example /etc/shorts-clipper.env
sudo nano /etc/shorts-clipper.env      # заполнить, обязательно CLIPPER_SECRET_KEY
sudo chown root:clipper /etc/shorts-clipper.env
sudo chmod 640 /etc/shorts-clipper.env
```

Ключ генерируется так:

```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

### 4. Служба

```bash
sudo cp deploy/shorts-clipper.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now shorts-clipper
journalctl -u shorts-clipper -f
```

В логе один раз появятся email и пароль администратора — сохраните и сразу
смените пароль через интерфейс.

### 5. Домен и HTTPS

```bash
sudo cp deploy/nginx.conf /etc/nginx/sites-available/shorts-clipper
sudo sed -i 's/example.com/ВАШ-ДОМЕН/g' /etc/nginx/sites-available/shorts-clipper
sudo ln -s /etc/nginx/sites-available/shorts-clipper /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d ВАШ-ДОМЕН
```

### 6. Firewall

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
```

Порт 8000 наружу **не открывать** — gunicorn слушает только localhost.

## Проверка после установки

```bash
# 1. HTTP переадресуется на HTTPS
curl -I http://ВАШ-ДОМЕН | grep -i location

# 2. Заголовки безопасности на месте
curl -sI https://ВАШ-ДОМЕН/login | grep -iE 'strict-transport|x-frame|content-security'

# 3. Приложение видит HTTPS (cookie должна быть Secure)
curl -sI https://ВАШ-ДОМЕН/login | grep -i set-cookie

# 4. Порт приложения закрыт снаружи

```

Дополнительно прогоните сайт через https://securityheaders.com и
https://www.ssllabs.com/ssltest/ — обе проверки бесплатные.

## Этап 2: многопользовательский режим

Ограничения Этапа 1 сняты. Что изменилось:

- **Данные в базе, а не в JSON.** Исчез риск потерять все аккаунты при
  одновременной записи. По умолчанию SQLite (ничего ставить не нужно), переход
  на PostgreSQL — это `CLIPPER_DB_URL=postgresql://…` и `pip install "psycopg[binary]"`.
- **Очередь задач.** Сайт складывает задачи в таблицу, обрабатывает их
  отдельный процесс `worker.py`. Пользователи больше не мешают друг другу,
  каждый видит свою позицию в очереди.
- **Полная изоляция.** Клипы, логи и загрузки лежат в `data/<id-пользователя>/`.
  Чужое не видно, не скачивается и не удаляется.
- **Квоты.** Минуты видео в месяц, одновременные задачи, максимальная длина
  видео — настраиваются на каждого пользователя.
- **Журнал действий** — входы, изменения аккаунтов, удаления.
- **Удаление аккаунта удаляет файлы** — по-настоящему, вместе с видео.

### Запуск

Нужны ДВА процесса:

```bash
sudo systemctl enable --now shorts-clipper           # сайт
sudo systemctl enable --now shorts-clipper-worker@1  # обработка
```

Воркеров столько, сколько задач тянет видеокарта (для `large-v3-turbo` — один-два
на карту). Их можно вынести на отдельную машину: нужны только общая база и общая
папка `data/`.

### Перенос старых данных

```bash
python migrate_to_db.py --dry-run     # посмотреть, что будет
python migrate_to_db.py               # перенести
```

Пароли переносятся как есть — заново задавать не придётся, при первом входе хеш
автоматически усиливается. Старые файлы переименовываются в `*.migrated`.

### Что осталось (Этапы 3-4)

- Хранение файлов в S3 и автоочистка по расписанию.
- Юридические документы (соглашение, политика конфиденциальности).
- Ускорение рендера через NVENC.
- Раздел «Мои задачи» в интерфейсе с историей.

## Резервное копирование

Ежедневно сохраняйте `users.json` и `usage.json` — в них аккаунты и статистика:

```bash
sudo -u clipper mkdir -p /opt/shorts-clipper/backups
sudo -u clipper cp /opt/shorts-clipper/users.json \
    /opt/shorts-clipper/backups/users-$(date +%F).json
```

Помните про риск из `AUDIT.md` (п. 2.2): при одновременной записи JSON может
испортиться, и без резервной копии **все аккаунты будут потеряны**. Это одна из
причин переходить на базу данных на Этапе 2.

Бэкапы содержат персональные данные — храните их зашифрованными.

## Очистка диска (пока нет автоматики)

Исходные видео в `work/` не удаляются никогда и занимают гигабайты. Временное
решение — задание в cron:

```bash
# /etc/cron.d/shorts-clipper-cleanup
0 4 * * * clipper find /opt/shorts-clipper/work -name 'source.mp4' -mtime +2 -delete
0 4 * * * clipper find /opt/shorts-clipper/web_uploads -type f -mtime +2 -delete
0 5 * * 0 clipper find /opt/shorts-clipper/clips -name '*.mp4' -mtime +30 -delete
```

Учтите: удаление `source.mp4` обнуляет кеш, и повторная обработка того же видео
пойдёт с нуля.

## Замеры и планирование мощностей

Перед настройкой автомасштабирования нужны **реальные** цифры с вашей карты.
Оценки «из общих соображений» дают неверные пороги: слишком высокие — люди ждут,
слишком низкие — вы платите за простой.

Метрики за неделю (только для администратора):

```
GET /api/admin/metrics?days=7
```

Что в ответе:

| Поле | Смысл |
|---|---|
| `by_stage` | среднее и p95 по каждому этапу в секундах |
| `total_seconds` | сколько занимает задача целиком |
| `wait_seconds` | сколько люди ждут в очереди — главный показатель качества |
| `gpu_hours_per_day` | сколько GPU-часов уходит в сутки |
| `gpus_avg` | сколько карт нужно в среднем (пик обычно в 2–3 раза выше) |
| `error_rate` | доля упавших задач, % |

Считайте нужное число карт так: `gpus_avg × 3` для пика, плюс одна тёплая
в резерве. Ориентируйтесь на цель «p95 ожидания меньше 2 минут» — полное
отсутствие очереди означает оплату простаивающих карт.

## Мониторинг

```
GET /healthz        # без авторизации, для системы мониторинга
```

Отвечает **503**, если в очереди есть задачи, а живых воркеров нет — это самый
частый сбой, который иначе замечают только по жалобам пользователей. Заведите
оповещение на этот код.

Персональных данных ответ не содержит: только длина очереди, число задач
в работе и число воркеров.

## Кодировщик видео

NVENC определяется автоматически — не по списку кодировщиков ffmpeg (наличие
в списке не гарантирует работоспособность), а пробным кодированием. Если карты
нет, используется libx264, и локальный запуск не ломается.

NVENC — отдельный аппаратный блок карты: он не отнимает вычислительные ядра,
поэтому рендер одного клипа идёт параллельно с распознаванием речи другого.

Принудительно отключить: `CLIPPER_ENCODER=libx264`.

## Повторы при сбоях

Задача не умирает от временного сбоя. Если YouTube ответил «подтвердите, что вы
не робот», LLM упёрлась в лимит, моргнула сеть или на карте кончилась память —
задача автоматически возвращается в очередь: до 3 попыток с паузами 1, 5 и 15
минут. Пользователь ничего не делает.

Устойчивые причины повторов **не** вызывают: видео без распознаваемой речи и на
третий раз останется без речи, а время видеокарты будет потрачено зря. Такие
задачи сразу помечаются ошибкой с понятным текстом.

## Резервное копирование

```bash
sudo systemctl enable --now shorts-clipper-backup   # раз в сутки
python backup.py --list                             # список копий
python backup.py --restore clipper-20260807.db.gz   # восстановление
```

Каждая копия **проверяется сразу после создания** — читается и сверяется
целостность. Непроверенная копия не является резервной копией: о её негодности
узнают в тот момент, когда она единственная и уже нужна.

При восстановлении прежняя база не удаляется, а отодвигается в сторону —
иначе откатиться после неудачного восстановления будет нечем.

**Обязательно настройте отправку копий за пределы сервера.** Копия рядом
с базой не спасает ни от отказа диска, ни от взлома. В копии персональные
данные — храните зашифрованной. Например:

```bash
# в cron, после ежедневной копии
rclone copy /opt/shorts-clipper/backups remote:clipper-backups --max-age 25h
```

Раз в квартал проверяйте восстановление на тестовой машине. Копии, которые
никогда не восстанавливали, регулярно оказываются нерабочими.

## Уведомления о готовности

Обработка идёт 15+ минут — держать вкладку открытой никто не будет. Настройте
SMTP в `/etc/shorts-clipper.env` (см. `deploy/env.example`), и пользователи
начнут получать письмо о готовности. Переключатель есть у каждого в разделе
«Мои задачи».

Если SMTP не настроен, письма просто не отправляются и переключатель скрыт —
он не должен обещать того, чего не будет. Сбой почтового сервера никогда не
влияет на обработку: клипы важнее письма.

В письме указывается срок хранения клипов — иначе человек вернётся через месяц
и не найдёт свои файлы.

Повторные письма исключены: отметка об отправке ставится атомарно, поэтому
перезапуск воркера не приводит к дублям (проверено на 10 одновременных
попытках — уходит ровно одно письмо).

Адреса в логах маскируются (`iv***@mail.ru`): логи читают и хранят дольше,
чем следовало бы.

## Хранилище клипов: диск или S3

По умолчанию файлы лежат на диске сервера — этого достаточно, пока сайт
и обработка на одной машине.

**S3 становится обязательным**, как только воркеры начнут подниматься и гаснуть
на арендованных машинах: диск инстанса исчезает вместе с ним, и клипы пропадут.
Работает с любым S3-совместимым хранилищем — Selectel, Yandex Object Storage,
Cloudflare R2, MinIO, AWS.

```bash
pip install boto3
# затем задать CLIPPER_STORAGE=s3 и CLIPPER_S3_* в /etc/shorts-clipper.env
```

**Бакет должен быть закрытым.** Клипы отдаются подписанными ссылками со сроком
жизни 1 час: этого хватает, чтобы скачать большой файл, и мало, чтобы утёкшая
ссылка долго оставалась рабочей. Открытый бакет означает, что чужие видео
с лицами и голосами доступны любому, кто подсмотрит адрес.

Файлы отдаёт само хранилище, а не приложение: сервер не тратит на раздачу ни
трафик, ни время.

### Проверка на живом бакете

Режим S3 у меня протестирован против заглушки (22 проверки: ключи, подписанные
ссылки, изоляция, удаление), но **живой бакет проверьте сами** — учётные данные
и права доступа заглушкой не проверить:

```bash
# 1. доступность бакета
python -c "import storage; print(storage.check())"

# 2. полный цикл на тестовом пользователе
python worker.py        # обработать одно короткое видео
# в логе должно появиться: [хранилище] выгружено файлов: N

# 3. проверить, что бакет ЗАКРЫТ (должно быть 403)
curl -I https://ВАШ-ЭНДПОИНТ/ВАШ-БАКЕТ/clips/тестовый-ключ.mp4
```

Третий пункт не пропускайте: открытый бакет — самая частая ошибка в такой
схеме, и обнаруживается она обычно поздно.

### Стоимость

Считайте не только хранение, но и **исходящий трафик**: при 200 задачах в день
это порядка 100+ ГБ в месяц скачиваний. У части провайдеров (Cloudflare R2)
исходящий трафик бесплатный, у других он может стоить дороже самого хранения.

## Структура кода

`web.py` разнесён: было 2303 строки с вёрсткой и скриптами внутри Python-строк,
стало 1033 строки только с логикой.

```
web.py                 маршруты и логика
templates/index.html   разметка панели
templates/login.html   разметка входа
static/css/app.css     стили панели
static/js/app.js       скрипты панели
static/css/login.css   стили входа
static/js/login.js     скрипты входа
```

Правки интерфейса теперь делаются в обычных html/css/js файлах, с подсветкой
синтаксиса и без риска сломать Python-строку.

### Ужесточённая политика безопасности

Скрипты вынесены в файлы, а встроенные `onclick=` заменены делегированием
событий, поэтому из CSP убрано `script-src 'unsafe-inline'`:

```
script-src 'self'
```

Это главная защита от внедрения чужого кода через содержимое страницы: даже
если в разметку попадёт `<script>`, браузер его не выполнит.

Если добавляете обработчик на кнопку, **не пишите `onclick=`** — он будет
заблокирован. Вместо этого:

```html
<button data-act="myAction" data-arg="значение">Кнопка</button>
```

и добавьте `myAction` в объект `ACTIONS` в конце `static/js/app.js`.

### Ссылка для связи с администратором

Задаётся одной переменной, формат распознаётся сам:

```bash
CLIPPER_CONTACT=@ваш_телеграм        # → https://t.me/ваш_телеграм
CLIPPER_CONTACT=help@ваш-домен.ru    # → mailto:
CLIPPER_CONTACT=https://vk.com/вы    # → как есть
```

Ссылка появляется в шапке. Оплаты на сайте нет — продление доступа только
через администратора.

## Запуск через Docker (рекомендуется)

Вместо ручной установки Python, CUDA и PyTorch:

```bash
cp deploy/env.example .env
nano .env                       # обязательно CLIPPER_SECRET_KEY
docker compose up -d --build
```

Поднимутся четыре службы: сайт, воркер, очистка диска, копирование базы.

```bash
docker compose ps                        # состояние
docker compose logs -f worker            # логи обработки
docker compose up -d --scale worker=2    # вторая карта
docker compose down                      # остановить
```

Первый пароль администратора появится один раз в `docker compose logs web`.

### Два образа вместо одного

| | Образ сайта | Образ воркера |
|---|---|---|
| Основа | python:3.12-slim | CUDA 12.4 + cuDNN |
| Что внутри | Flask, gunicorn | PyTorch, Whisper, ffmpeg, модели |
| Размер | десятки МБ | несколько ГБ |
| Сборка | около минуты | десятки минут |

Разделение сделано намеренно: сайту незачем тащить PyTorch, а его образ должен
подниматься мгновенно. Очистка и копирование используют лёгкий образ сайта.

### Модели вшиты в образ воркера

Это главное для аренды машин. Холодный старт складывается из: получить
инстанс → скачать образ → скачать модели → загрузить в память. Модели внутри
образа убирают третий шаг: у провайдеров образ кешируется на хосте, а модель
качалась бы заново на каждой новой машине.

Сменить модель при сборке:

```bash
CLIPPER_WHISPER_MODEL=medium docker compose build worker
```

### Требования к хосту

Для доступа контейнера к видеокарте нужен **NVIDIA Container Toolkit**:
https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/

Проверка:

```bash
docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi
```

### Что проверить после первой сборки

```bash
# 1. Видеокарта видна воркеру
docker compose exec worker python3 -c "import torch; print(torch.cuda.is_available())"

# 2. NVENC доступен (иначе рендер пойдёт на процессоре — медленнее)
docker compose exec worker ffmpeg -hide_banner -encoders | grep nvenc

# 3. Сайт отвечает
curl -s localhost:8000/healthz
```

Второй пункт не пропускайте: ffmpeg из репозитория Ubuntu обычно собран
с NVENC, но это зависит от версии. Если его нет, поставьте
`CLIPPER_ENCODER=libx264` — работать будет, просто медленнее.

### Секреты в образ не попадают

`.dockerignore` исключает `.env`, `.flask_secret`, базу, бэкапы и клипы. Это
важно: образ уходит в реестр и на арендованные машины, и секрет внутри него
означал бы возможность подделать любую сессию.

Проверьте перед публикацией образа:

```bash
docker compose run --rm web ls -la | grep -E "\.env|flask_secret" || echo "чисто"
```

### PostgreSQL, когда SQLite перестанет справляться

```bash
# в .env: CLIPPER_DB_URL=postgresql://clipper:ПАРОЛЬ@db/clipper
#         POSTGRES_PASSWORD=ПАРОЛЬ
docker compose --profile postgres up -d
```

### Почему тесты на ядро важнее, чем кажется

Самое хрупкое место сервиса — ответ языковой модели: это текст, и он
регулярно приходит повреждённым. Обрезанным по лимиту токенов, в markdown-
обёртке, с висячими запятыми. Каждый неразобранный ответ означает потерянный
прогон и потраченное время видеокарты, поэтому разбор проверяется на всех
известных видах порчи, включая обрыв на середине.

Проверка на обрезанный ответ подтверждает главное: из повреждённого JSON
вытаскиваются все ЦЕЛЫЕ клипы, и прогон продолжается вместо падения.


### Почему появился набор tests_ui.py

Кнопка может выглядеть исправной и при этом ничего не делать: обработчик на
месте, запрос уходит, а маршрута на сервере нет — в консоли браузера 404,
на экране тишина. Так сломались «Сбросить статистику» и переключатель писем:
оба маршрута были случайно затёрты при правках соседнего кода.

Теперь набор берёт все адреса, которые дёргает `static/js/*.js`, и проверяет,
что каждый существует на сервере, а затем нажимает каждую кнопку настоящим
запросом. Отдельно сверяется, что скрипт не обращается к элементам, которых
нет в разметке.
